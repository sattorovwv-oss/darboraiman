# GitHub Pages + Supabase (без отдельного Python-хостинга)

1. Таблица `reviews` уже создана? Повторять `schema.sql` не нужно. Выполните `rate-limit.sql` в SQL Editor.
2. Supabase → Edge Functions → Secrets: добавьте НОВЫЙ `GROQ_API_KEY`. Не используйте опубликованный в чате ключ. SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY обычно предоставляются функциям платформой автоматически.
3. Edge Functions → Deploy a new function → Via Editor. Имя функции: **reviews**. Замените код `index.ts` содержимым `functions/reviews/index.ts`, Deploy.
4. В настройках reviews отключите **Verify JWT / Enforce JWT verification**. Это публичная форма без входа, серверные ключи в браузер не передаются. Функция самостоятельно проверяет поля, лимитирует попытки, вызывает Groq и только потом сохраняет отзыв.
5. Загрузите файлы проекта в GitHub-репозиторий `sattorovwv-oss/darboraiman`, включая `.github/workflows/pages.yml`. Изменения в облачной рабочей папке ещё НЕ загружены в GitHub.
6. Репозиторий → Settings → Pages → Source: **GitHub Actions**. Запустите workflow Publish portfolio, если не запустился автоматически. После успешной публикации ожидаемый адрес: https://sattorovwv-oss.github.io/darboraiman/ . До выполнения этих шагов ссылка может не работать.
7. Проверьте: отзывы загружаются, корректный отзыв появляется, оскорбительный отклоняется, другой браузер видит тот же список, сортировка и статистика работают.

Браузер отправляет запросы только в функцию; таблица закрыта для anon/authenticated. CORS разрешает публичные запросы без cookies. Ограничение по IP снижает частоту, но не гарантирует защиту от распределённого спама. ИИ тоже может ошибаться. Бесплатные лимиты Supabase/Groq/GitHub применяются независимо; уточняйте актуальные квоты.

Локальный Python-сервер остаётся альтернативой и использует OpenAI. Версия для GitHub Pages использует Groq. Отдельный HTML с file:// сохраняет режим просмотра: отправка отключена. Для живых отзывов используйте опубликованный сайт.
